# โปรแกรมแปลเกมด้วย Claude — สเปก (โปรเจกต์ย่อย 1)

วันที่: 2026-10-03 · สถานะ: รอผู้ใช้ตรวจ

## 1. เป้าหมาย

โปรแกรมหน้าต่างบนเครื่องนี้ (Windows, ใช้คนเดียว) ไว้แปลเกม **Unreal Engine** เป็นภาษาไทยด้วย Claude API
ผู้ใช้ใส่ API key แล้วเลือกรุ่น Claude เลือกโฟลเดอร์เกม กดแปล แล้วกดติดตั้งลงเกม
โปรแกรมมี **ความจำที่สะสมข้ามเกม** (สไตล์ บทเรียน อภิธานศัพท์ คลังคำแปล) ทำให้แปลเกมถัดไปได้ดีขึ้นและถูกลง

**เกณฑ์ว่าสำเร็จ:** รัน Maneater ด้วยโปรแกรมนี้แล้วได้ไฟล์ `_P.pak` ที่เกมโหลดได้ ตัวตรวจผ่านทุกข้อความ และเกมแสดงภาษาไทย (เทียบกับงานที่ทำมือเมื่อ 2026-10-03)

### ไม่ทำในรอบนี้
- เอนจินอื่นนอกจาก Unreal (Unity, RPG Maker, Ren'Py) — ออกแบบให้เพิ่มทีหลังได้
- แตกไฟล์ pak ที่บีบอัดแบบ Oodle หรือเข้ารหัส AES — ให้ผู้ใช้เลือกไฟล์ `Game.locres` ที่แตกเองด้วย FModel แทน
- ติดตั้งตัวข้ามลายเซ็นไฟล์ (sig bypass) — มีแค่คำเตือน
- ชั้นหนังสือ (เว็บตรวจคำแปล) — เป็นโปรเจกต์ย่อย 2 ส่วนรอบนี้จะเขียนแค่ไฟล์ "หนังสือ" ให้เว็บนำไปใช้ได้ (หัวข้อ 7)
- การค้นคำแปลแบบใกล้เคียง (fuzzy) ในคลังคำแปล และการแพ็กเป็นไฟล์ .exe

## 2. หน้าจอและขั้นตอน (UI ภาษาไทย, Tkinter)

1. **ตั้งค่า:** ช่อง API key (ซ่อนตัวอักษร มีติ๊ก "จำไว้ในเครื่องนี้") และเมนูเลือกรุ่น
   - Opus 5.5 `claude-opus-5-5` (ค่าเริ่มต้น)
   - Sonnet 5.5 `claude-sonnet-5-5`
   - Haiku 4.5 `claude-haiku-4-5`
   - Fable 5.1 `claude-fable-5-1`
2. **เลือกเกม → สแกน:** หาแหล่งข้อความตามลำดับ
   1. มีม็อดไทยใน `Content/Paks` อยู่แล้ว (ไฟล์ `*_P.pak` ที่มี `Game.locres` ภาษาไทย) → แปลเฉพาะข้อความที่ยังเป็นอังกฤษ และใช้คำของม็อดเป็นอภิธานศัพท์
   2. แตก `Localization/Game/en/Game.locres` จาก pak หลักได้ (pak v3–v9, zlib หรือไม่บีบอัด) → แปลทั้งหมด
   3. แตกไม่ได้ (Oodle, เข้ารหัส, pak v11+) → ให้เลือกไฟล์ `Game.locres` เอง

   แสดงสรุปจำนวน: ทั้งหมด / แปลแล้ว / ต้องแปล / ข้าม (เครดิต, ดีบัก, ไม่มีตัวอักษร, ชื่อตัวแปร) / ดึงจากคลังคำแปลได้ พร้อมราคาประมาณเป็น USD
   เตือนเพิ่มถ้าเจอ `*.sig` (ต้องมีตัวข้ามลายเซ็น) หรือถ้าเกมเปิดอยู่
3. **แปล:** ปุ่มแปล ปุ่มหยุด แถบความคืบหน้า และค่าใช้จ่ายจริง (จาก `usage`) มีปุ่ม "ลองแปล 10 ข้อความ" ไว้เช็ค key/สไตล์ก่อนสั่งแปลทั้งเกม
   งานบันทึกทีละชุดลง `work/<game>/` ถ้าปิดแล้วเปิดใหม่จะทำต่อจากชุดที่ค้างโดยไม่เสียเงินซ้ำ
4. **ติดตั้ง:** สร้าง pak ที่มี `Game.locres` และฟอนต์ไทย
   - ชื่อไฟล์: ถ้าต่อยอดม็อดให้ใช้ชื่อไฟล์ม็อดเดิม ถ้าไม่ใช่ให้ตั้งเป็น `<ชื่อโฟลเดอร์โปรเจกต์เกม>_Thai_P.pak`
   - ฟอนต์: ถ้าต่อยอดม็อดให้ใช้ฟอนต์ในม็อดนั้น ถ้าไม่ใช่ ให้ทับทุก `*.ufont` และ `Engine/Content/Slate/Fonts/*.ttf` ที่อยู่ในรายชื่อไฟล์ของ pak หลักด้วย **Sarabun** (OFL มีทั้งไทยและละติน — NotoSansThai ไม่มีตัวอักษรละติน ใช้ไม่ได้) ชื่อที่มี Bold/Black/Heavy ใช้ Sarabun-Bold ที่เหลือใช้ Sarabun-Regular ตามแบบม็อด JIM
   - สำรองไฟล์ที่จะถูกทับไว้ใน `work/<game>/backup/` ก่อน แล้วคัดลอกลง `Content/Paks`
5. **สอนเพิ่ม (กล่องข้อความ):** ผู้ใช้พิมพ์คำแนะนำ เช่น "Infamy = ค่าหัว" → บันทึกเข้าอภิธานศัพท์ของเกมหรือ `style_th.md` ทันที
6. **จบเกม → สรุปบทเรียน:** Claude เสนอบทเรียนใหม่ 3–10 ข้อ แสดงเป็นรายการติ๊กเลือก ข้อที่ผู้ใช้ติ๊กเท่านั้นจึงจะถูกบันทึก

## 3. โครงสร้างโปรเจกต์

```
game-translator/
  app.pyw            หน้าต่าง Tkinter อย่างเดียว เรียกใช้โมดูลใน gt/
  gt/
    ue_pak.py        อ่าน pak v3–v9 (none/zlib), อ่านรายชื่อไฟล์ v11, เขียน pak v5 แบบไม่บีบอัด
    locres.py        อ่าน/เขียน locres v2/v3 (คง hash เดิม) — ยกมาจากงาน Maneater ที่ทดสอบแล้ว
    scan.py          หาแหล่งข้อความ, รวมรายการที่ต้องแปล, กฎการข้าม
    validate.py      ตรวจแท็ก/ตัวแปร/ขึ้นบรรทัด/ช่องว่างหัวท้าย/มีภาษาไทย/ช่วงยาวไม่มีวรรค
    translate.py     แบ่งชุด, เรียก Claude, ตรวจ, ส่งแก้ 1 รอบ, คิดค่าใช้จ่าย, resume
    memory.py        โหลด/บันทึก style, lessons, glossary, TM; สรุปบทเรียน
    book.py          เขียนไฟล์หนังสือ (สัญญาข้อมูลกับชั้นหนังสือ)
    install.py       สร้าง pak (locres + ฟอนต์), สำรองไฟล์, ติดตั้ง
  fonts/             Sarabun-Regular.ttf, Sarabun-Bold.ttf (OFL) + OFL.txt
  memory/            style_th.md, lessons.md, glossary/<game>.json, tm.jsonl
  books/<game>.json
  work/<game>/       ชุดงานที่แปลแล้ว, backup/
  settings.json      รุ่นที่เลือก + API key (เฉพาะเมื่อติ๊ก "จำไว้")
  tests/             สคริปต์ assert ทดสอบแบบไม่ต้องใช้ API
```

ใช้ Python 3.12 ที่มีอยู่ในเครื่อง และ dependency ภายนอกตัวเดียวคือ `anthropic` (SDK ทางการ)

## 4. การไหลของข้อมูล

```
scan  → รายการ {n, ns, key, en, th_เดิม?}
      → กฎข้าม + ดึงจาก TM (ตรงเป๊ะ)          → ที่เหลือคือ "ต้องแปล"
translate (ชุดละ ~150 ข้อความ / ~12k ตัวอักษร, พร้อมกัน 4 ชุด)
      → system = style_th + lessons + glossary ทั้งเกม   (cache_control: ephemeral; ชุดแรกรันเดี่ยวเพื่อเขียน cache ก่อนรันขนาน)
      → user   = JSON [{id, en, ns}]
      → ผลลัพธ์ structured output {items:[{id, th, type}]}
      → validate → ข้อที่ไม่ผ่านส่งแก้ 1 รอบพร้อมบอกจุดผิด → ยังไม่ผ่าน = คงอังกฤษ + รายงาน
      → บันทึก work/<game>/batchNN.json, ต่อท้าย tm.jsonl, อัปเดต book
install → locres ใหม่ (คง hash เดิมทุกตัว) + ฟอนต์ → pak v5 → backup → คัดลอกลง Paks
```

## 5. การเรียก Claude

- ใช้ `anthropic.Anthropic(api_key=...)` และ `client.messages.stream(...).get_final_message()` โดยตั้ง `max_tokens` 32000
- คงค่าเริ่มต้นของ thinking (adaptive) และตั้ง `output_config.effort = "medium"`
- `output_config.format` เป็น JSON schema: `items[]` ซึ่งมี `id:int`, `th:str`, `type: dialogue|description|document|ui|other`
- `fallbacks: "default"` พร้อม beta `server-side-fallback-2026-07-01` สำหรับ Opus 5.5 / Sonnet 5.5 / Fable 5.1 ถ้า `stop_reason == "refusal"` ให้คงชุดนั้นเป็นอังกฤษและบันทึก log
- ข้อผิดพลาด: 401 → "API key ไม่ถูกต้อง", 429/5xx → SDK retry ให้เอง (max_retries=4), เน็ตหลุด → หยุดแล้วกลับมาทำต่อได้
- ราคาประมาณ: นับตัวอักษร ÷ 4 = token ขาเข้า, ภาษาไทยขาออก ≈ ตัวอักษรอังกฤษ × 0.9 token, คูณตารางราคาในโค้ด (Opus 5.5 $4/$20, Sonnet 5.5 $2/$10, Haiku 4.5 $1/$5, Fable 5.1 $10/$50 ต่อ 1M token) ค่าจริงคำนวณจาก `usage` รวม cache read/write

## 6. ความจำและการเรียนรู้

| ไฟล์ | เนื้อหา | ตั้งต้นจาก |
|---|---|---|
| `memory/style_th.md` | กฎสไตล์ไทย: เว้นวรรคทุก ~25–35 ตัวอักษร, ห้ามแตะแท็ก/ตัวแปร/`\r\n`, น้ำเสียงตามประเภทตัวละคร, ไม่แปลรายชื่อเครดิต, ตัวพิมพ์ใหญ่ทั้งหมด → ไทยปกติ | BRIEF.md ของ Maneater + ม็อด JIM |
| `memory/lessons.md` | บทเรียนเทคนิค: locres/pak, ฟอนต์, `.sig`, Oodle, ตำแหน่งไฟล์ | memory `game-thai-translation-lessons` |
| `memory/glossary/<game>.json` | รายการ `{en, th, category, tone, note, dnt}` ของเกมนั้น (โครงแบบ Weblate ฉบับย่อ) | คำสั้น (≤40 ตัวอักษร) จากม็อดเดิม + คำที่ผู้ใช้สอน + คำสั้นที่ Claude แปลใหม่ |
| `memory/tm.jsonl` | `{en, th, game, model, date}` ทุกข้อความที่ผ่านตัวตรวจ | Maneater 2026-10-03 (~6,300 คู่) |

- ฟิลด์ของอภิธานศัพท์: `category` ∈ character, location, item, skill, creature, ui, other · `tone` = น้ำเสียง/สรรพนามของตัวละคร (ข้อความอิสระ) · `note` = บริบท · `dnt` = ห้ามแปล (คงอังกฤษ)
- ส่งอภิธานศัพท์ทั้งเกม (สูงสุด 1,500 คำ) ไว้ใน system prompt ที่ cache แล้ว ไม่กรองเป็นรายชุด เพราะ cache read ราคาถูกมาก
- ตัวตรวจแบบเตือน (soft): คำในอภิธานศัพท์ (ยาว ≥3 ตัวอักษร, ไม่ใช่หมวด other) ที่ปรากฏในข้อความอังกฤษ ต้องมีคำไทยที่กำหนดอยู่ในคำแปล (หรือคงอังกฤษถ้า `dnt`) ถ้าไม่มี ให้ส่งแก้พร้อมระบุคำ
- ไม่ทำรอบนี้ (จดใน lessons.md): zero-width space + PyThaiNLP เพื่อตัดบรรทัด (ต้องทดสอบในเกมก่อน), เครื่องมือเอนจินอื่น (XUnity.AutoTranslator, AssetStudio, Translator++, Ren'Py)
- สรุปบทเรียน: ส่งรายการปัญหาที่ตัวตรวจเจอ + สิ่งที่ผู้ใช้สอน + ตัวอย่างคำแปล 40 คู่ แล้วขอบทเรียน 3–10 ข้อแบบ structured output → ผู้ใช้ติ๊กเลือก → ต่อท้าย `lessons.md` หรือ `style_th.md` พร้อมระบุวันที่และชื่อเกม

## 7. ไฟล์หนังสือ (สัญญาข้อมูลกับโปรเจกต์ย่อย 2)

`books/<game_id>.json`
```json
{"game": "Maneater", "game_id": "maneater", "engine": "UE4.25", "source": "mod+claude",
 "model": "claude-opus-5-5", "updated": "2026-10-03",
 "lines": [{"n": 1, "ns": "", "key": "C5DE…", "en": "…", "th": "…",
            "type": "dialogue|description|document|ui|other",
            "group": "Maneater_Dialog_DB", "status": "mod|claude|tm|edited|english"}]}
```
- `n` = ลำดับตาม locres เริ่มที่ 1 ไม่เปลี่ยนแม้แปลใหม่ ใช้เป็น "เลขบรรทัด" ให้อ้างอิงตอนแก้
- `group` = namespace หรือ prefix ของคีย์ (ถ้ามีความหมาย) ส่วนการแบ่งฉาก/ทางแยกแบบละเอียดเป็นงานของโปรเจกต์ 2
- ถ้าชั้นหนังสือแก้คำแปล ต้องเขียนกลับไฟล์นี้ (`status: edited`) และ TM แล้วกดติดตั้งใหม่ในโปรแกรมแปล

## 8. การทดสอบ

- `tests/test_formats.py`: locres อ่าน-เขียนได้ byte ตรงกับต้นฉบับ Maneater, pak v5 เขียนแล้วอ่านกลับได้ตรงกัน, อ่านรายชื่อไฟล์ใน pak v3 ของ JIM ได้
- `tests/test_validate.py`: กรณีแท็กหาย, `{0}` หาย, `\r\n` ไม่ครบ, ช่องว่างหัวท้าย, ไม่มีภาษาไทย, ช่วงยาวไม่มีวรรค
- `tests/test_pipeline.py`: รันทั้งท่อด้วยตัวแปลปลอม (คืนข้อความ "ไทย" + แท็กเดิม) บน Maneater → ได้ pak ที่อ่านกลับได้และนับจำนวนตรง
- ทดสอบจริง 1 ครั้งด้วย key ของผู้ใช้ผ่านปุ่ม "ลองแปล 10 ข้อความ" (ค่าใช้จ่ายไม่ถึง $0.10)
- ทดสอบในเกม: ติดตั้งลง Maneater แล้วเปิดเกม (affinity F) จับภาพหน้าต่างดูภาษาไทย

## 9. โปรเจกต์ย่อย 2 (ออกแบบรอบหน้า): ชั้นหนังสือ

เว็บบนเครื่อง (เปิดจากปุ่มในโปรแกรม): ชั้นแสดงหนังสือทุกเกม → หยิบเล่มออกมาอ่านทีละบรรทัดพร้อมเลขบรรทัด → แก้คำแปลแล้วเขียนกลับหนังสือ + ความจำ → กรองตามประเภท → แบ่งบท/ฉาก/ฉากจบตามคีย์ ตามที่ Claude เดา (มีป้ายบอกว่าเดา) หรือตามที่ผู้ใช้จัดเอง
